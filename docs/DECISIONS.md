# Decisions

| # | Decision | Why |
|---|---|---|
| 1 | `deploy_stack.py` uses boto3 CloudFormation change sets instead of shelling out to `aws cloudformation deploy`. | The CLI command cannot reuse the previous value of the `NoEcho` token parameter; change sets can (`UsePreviousValue`). Also removes a dependency on the CLI binary. |
| 2 | `setup_agent.py` refreshes the `live` alias by deleting and recreating it. | Updating an alias to point at the newly prepared version needs the new version number; delete + create (without routing config) snapshots DRAFT automatically and is simpler to read. The alias ID changes and is re-saved to `config.json`. |
| 3 | `config.json` gains one key, `todoist_secret_arn`. | `e2e_test.py` reads the token from Secrets Manager (so it is never typed again), and `cleanup.py` needs the ARN to purge the secret. The token itself is never stored. |
| 4 | `cleanup.py` force-deletes the secret after the stack is gone. | CloudFormation leaves secrets in a 30-day recovery window; "cleanup leaves zero resources". |
| 5 | The agent role is named `AmazonBedrockExecutionRoleForAgents_<stack>`. | Bedrock's documented naming convention; needs `CAPABILITY_NAMED_IAM`, which the spec already asks for. |
| 6 | Lambda handler is `handler.lambda_handler`; the template's inline code is only a placeholder. | The real zip is pushed straight after stack creation. |
| 7 | Routes live in `build_routes()` rather than a module-level dict. | A module-level `ROUTES = {...}` replaced by a TODO would break `import handler` in the starter; a function keeps the starter importable. |
| 8 | "Current weighted %" is reported as points earned of graded weight and the % on graded work; the implied grade for GPA uses the % on graded work. | Spec leaves it open. A student with 49/60 graded points is treated as a B+ (81.7%), not as failing. |
| 9 | `week` maps to the Todoist filter `7 days` exactly as specified; overdue tasks are not included. | Follows the spec; the agent can call `overdue` separately. |
| 10 | `complete_task` matches on all words of the query being in the title (exact title wins), using `GET /tasks`. | Predictable for students; never guesses between several matches. |
| 11 | `break_down_project` gives the parent task the due date of the last step. | Gives the parent a sensible date without extra date maths in Lambda. |
| 12 | Tests use moto's `mock_aws` against the real `boto3` code; `todoist_client` calls `urllib.request.urlopen` via the module so it can be monkeypatched. | Matches TESTING.md. |
| 13 | Dev venv is Python 3.14 on Windows; `moto` installs only with `--only-binary` there. | Local environment note, not a project requirement. |
| 14 | The Lambda role's log policy uses a hand-built log-group ARN instead of `!GetAtt ToolsLogGroup.Arn`. | First deploy failed: `GetAtt` makes CloudFormation call `logs:DescribeLogGroups` with the deployer's credentials, which a scoped IAM policy denied. Building the ARN removes that dependency. |
| 15 | `deploy_stack.py` prints the stack's `*_FAILED` reasons. | "See the console" is not helpful to beginners. |
| 16 | **Replaced the Bedrock Agent with a Converse API tool loop** in `app/agent_client.py` (approved by the user). | `CreateAgent` is refused for accounts without Bedrock Agents use in the last 12 months (see VERIFIED.md), so fresh student accounts cannot create agents. `setup_agent.py`, the agent role, the Lambda invoke permission and `agent_id`/`agent_alias_id` config keys were removed. |
| 17 | The Lambda keeps the Bedrock-Agents event/response contract; the app builds that event and calls `lambda.invoke`. | Handler and its tests are unchanged, and the Lambda would still work behind a real Bedrock Agent. |
| 18 | `functions.json` has an optional `json_schema` per parameter, used only by the Converse path. | First live run: Nova returned `ModelErrorException: invalid sequence as part of ToolUse` when asked to write JSON inside a string. Real object/array schemas are more reliable; `type: string` stays for Agents compatibility. |
| 19 | The app adds today's date to the system prompt and uses temperature 0. | Bedrock Agents injected the date itself; "next Friday" needs it. Temperature 0 is the most reliable setting for tool calls. |
| 20 | Conversation history lives in a module-level dict keyed by session id, and is saved only after a successful turn. | Simple to read; a failed call cannot leave a tool request without its result. History is lost when the Streamlit server restarts. |
| 21 | Stack capability changed from `CAPABILITY_NAMED_IAM` to `CAPABILITY_IAM`. | No named roles remain. |
| 22 | The agent loop is a **generator** (`stream_agent`) over `bedrock.converse_stream`; `ask_agent` just collects its events. | The UI shows words as they arrive (`st.write_stream`), a status line while tools run, and the trace afterwards. One loop serves the UI, the e2e test and the unit tests. |
| 23 | `<thinking>...</thinking>` text from Nova is hidden from the answer by `ThinkingFilter` (it copes with tags split across chunks) and shown, without the tags, in the reasoning trace. | Students saw the model's private notes in answers. Filtering while streaming cannot wait for the full message. |
| 24 | Speech lives in `app/voice.py`: finished sentences go to Polly in background threads, and the browser plays the clips in order from a queue kept in the main page. Default voice Ruth on the `generative` engine, falling back to `neural`. | Speech starts about 2-3 s after the first sentence instead of after the whole answer. Generative voices are the most natural Polly offers. The latency is Polly's (about 1-2.5 s per sentence generative, 0.4 s neural): set `polly_engine` to `neural` in `config.json` for a faster start. Markdown, emoji and grades ("B+") are cleaned up before speaking. |
| 25 | Audio is delivered with `st.iframe` (falls back to `components.html` on older Streamlit); the helper iframes are hidden with CSS. | `components.html` is deprecated and scheduled for removal; Streamlit has no built-in way to queue audio clips. This stays inside the existing stack (no new dependency). |
| 26 | `list_tasks` handles "this week" / "next week" (Monday to Sunday) and explicit `start_date` / `end_date` by comparing due dates in Python, and always prints real calendar dates. | Todoist's filter language has no reliable "this week"; the old code searched for a course called "THIS WEEK" and reported no tasks. The Lambda uses its own clock (UTC), so around midnight the week boundary can be one day off for students far from UTC. |
| 27 | Task tools are forgiving about due dates: if Todoist answers 400 to a due string, the task is created without a date and the reply says so. The agent is told to give `break_down_project` exact YYYY-MM-DD dates. | Live: phrases like "the day before the deadline" made Todoist reject the whole request, so nothing was created and the model sometimes gave up. |
| 28 | `grade_needed` words its result as "you already have X points and a Y needs Z in total". | "(49 of 85 points earned)" was read by the model as marks on the final. |
| 29 | In the e2e test, step 10 (Chemistry) needs only a friendly reply naming the course, and step 8 must check the OS grade but does not have to create the DB project a second time. | By then the conversation already shows the saved courses, and the project already exists from step 6; not repeating work is correct (and avoids duplicate Todoist projects). This is a small deviation from the SPEC.md section 8 wording. |
